## Fix before next TestFlight build

### R1 (HIGH, new) — Level-up popup consumes battle RNG; refresh rerolls enemy actions the player already watched
`LevelUpPopup` (`src/ui/LevelUpPopup.js:133-200`) builds its panel with plain `scene.add.text` — each Phaser Text burns ~31 `Math.random()` draws via UUID generation. During an enemy phase, `onUnitDone` (`BattleScene.js:10010-10019`) captures the checkpoint (which reseeds the global RNG to the battle stream), **then** presents queued popups — burning ~150+ battle-RNG draws. The next enemy attacks from a shifted stream position; on refresh, resume skips the acted enemy and the popup, replaying from the unshifted position — different hit/crit outcomes than what was shown. This breaks the suspend contract ("a refresh can never reroll a resolved outcome") and re-enables enemy-phase save-scumming — the exact thing P4's checkpoint exists to prevent. This is the known `presentationText` hazard; the popup was never converted. Fix: render `LevelUpPopup` through `presentationText` (or the same RNG-swap guard), and add a live-vs-resume stream-equivalence test across a popup boundary.

### R2 (HIGH, new) — Three teaching hints can never display
`showContextualHint`'s new gate requires `battleState` be absent or `PLAYER_IDLE` (`src/ui/HintDisplay.js:257-261`) and drops non-qualifying hints silently (no deferral). But `battle_consumable_supply` / `battle_staff_scope` fire from `MobileBattleHUD.showMenu` after `UNIT_ACTION_MENU` is set, and `battle_heal_uses` fires mid-heal-flow — all permanently suppressed. `battle_heal_uses` is a regression (it displayed before this change). Tests miss it because the fixture scene has no `battleState`. Fix: defer these to the next `PLAYER_IDLE` (the first-turn hints already have that pattern at `BattleScene.js:9350`) or exempt menu-context hints, and give the test fixture a `battleState`.

### R3 (HIGH) — Failing test: seed-11 wall-detour regression
`tests/sim/RunSimulationDriver.test.js` "seed 11 reaches the cleared Act 1 throne" — a test this wave added — fails: seed 11 on Normal now loses at the third node (recruit battle) and never reaches the boss. Something landed after the recorded verification run and shifted the seeded outcome. Determine whether a late change regressed sim behavior or merely staled a brittle seed anchor; fix or re-anchor with justification. The tree must be green at check-in.

### R4 (MED-HIGH) — U6: reachable mobile dead-tap state after undo
`InputController.js:487-493` opens the action menu from an own-tile tap in `UNIT_SELECTED` without registering `_selectionMenu` (only `handleIdleClick` :383 registers it). Repro: select → move → Back (`undoMove` re-selects into `UNIT_SELECTED`) → tap own tile → menu open but `isSelectionMenu()` false → `handleActionMenuClick` (:533) silently swallows every grid tap — no empty-tile exit, no ally switch. This resurrects the exact clunkiness U6 was written to fix, on its most common path (undo). Fix: register `_selectionMenu` at that open site. Companion (LOW): in a registered selection menu, tapping an inspectable occupant that is neither ready ally nor mobile enemy (:541-542) returns silently — should inspect or cancel, never nothing.
