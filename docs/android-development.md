# Android development setup

## Current setup

- Capacitor 8.5.2 (`@capacitor/android`), Gradle 8.14.3, compile and target SDK 36, min SDK 24 (Android 7). Java 21 and the Android SDK (Android Studio installs both).
- Native project: `android/`. Generated by `npx cap add android`; the edits below are ours.
- App name: Rogue Dawn (`app_name` in `android/app/src/main/res/values/strings.xml`). Application ID: `com.davechen.emblemrogue`, the same as the iOS bundle ID and the Play Console package name. It can never change once a build is on Play.
- Version name `0.1.0` (`android/app/build.gradle`); the version code comes from `-PversionCode` (CI: 100 + the workflow's run number).
- The app packages `dist` locally and is offline by default, like the iOS app (`VITE_CLOUD_ENABLED` unset), so its Play Data safety answer is "No data collected".

## Development workflow

```sh
npm ci
npm run android:sync   # build the web game and copy it into android/
npm run android:open   # open the project in Android Studio
```

In Android Studio pick an emulator or a USB-connected phone and press Run. `android:sync` copies the build into `android/app/src/main/assets/public/`, which is ignored by git like the iOS copy.

## What the Android app does differently

- **Back button / gesture** (`src/utils/androidBackButton.js`): Back is the game's Cancel action on the input bus (the gamepad's B), so the scene or overlay holding input focus handles it. At the title screen's root menu (`TitleScene.isAtRootMenu()`), Back sends the app to the background (`App.minimizeApp`); it never closes it. Without a listener, Capacitor's default would leave Back doing nothing at the root.
- **Orientation** (`MainActivity.java`): phones turn freely (portrait mode is on by default). A screen whose shorter side is at least 600dp, the same line as `PHONE_MAX_SHORT_SIDE` in `src/utils/portraitBattle.js`, is a tablet and is locked to landscape, like the iPad app (the web side already treats a native non-phone screen as landscape-locked, `isLandscapeLockedShell`). The manifest declares `android:appCategory="game"`: Android 16 ignores orientation locks on large screens for apps targeting SDK 36 unless they are games.
- **Full screen**: the system bars are hidden (immersive; an edge swipe shows them briefly), as the iOS app hides its status bar. Capacitor's SystemBars passes the cutout's safe-area insets to CSS `env()` (the page uses `viewport-fit=cover`).
- **Saves**: `localStorage` as everywhere; the native save mirror (`src/utils/nativeSaveMirror.js`) runs on Android too, since it checks for a native bridge and the Filesystem plugin rather than for iOS. Its `LIBRARY` folder is the app's private files directory on Android.
- **Icons and splash**: `npm run gen:icons` writes the launcher icons (legacy, round and the adaptive icon's foreground, on `#07060B`) and the launch screens from the same sources as the iOS app. `tests/GameIdentity.test.js` holds the name, application ID and orientation rules.

## Google Play from GitHub Actions

`.github/workflows/play.yml` builds the signed bundle on an Ubuntu runner: CI must have passed on the commit, the music is re-encoded at the iOS app's lighter quality (`tools/ios/compactMusic.mjs`; the bundle is about 175 MB, Play's limit is 200 MB), the web game is built and synced, `./gradlew bundleRelease` signs it with the upload key, and the bundle is checked (size, the web game inside it, the signature).

- **Modes:** `upload` (default) sends the bundle to a Play track (`internal` by default; `alpha` is closed testing, `beta` open testing) with `release_status` `completed` (testers get it now) or `draft`. `build` keeps the signed bundle as the run's `android-bundle` artifact. A pull request that changes `android/`, `capacitor.config.*` or the workflow builds it (signed, with the bundle kept, when the secrets are set; unsigned otherwise).
- **First upload:** the Play API can only add releases to an app that already has one, so the first bundle goes up by hand: download `android-bundle` from a `build` run (or the pull request's run) and upload it in Play Console → Test and release → Testing → Internal testing → Create new release. Accept Play App Signing (Google-generated app signing key) there.
- **If Play says "Only releases with status draft may be created on draft app":** run with `release_status: draft` and roll the release out in Play Console until the app has been through its first release.
- **Secrets:** `ANDROID_UPLOAD_KEYSTORE_BASE64` (the `.jks`, base64), `ANDROID_UPLOAD_KEYSTORE_PASSWORD`, `ANDROID_UPLOAD_KEY_ALIAS`, `ANDROID_UPLOAD_KEY_PASSWORD`; for uploads, `PLAY_SERVICE_ACCOUNT_JSON` (a Google Cloud service account's JSON key with the Google Play Android Developer API enabled, invited in Play Console → Users and permissions with release permissions for this app).
- **Version code:** 100 + the run number (the `version_code` input overrides it). Play refuses a code it has seen, so re-running a run that already uploaded needs a new run, not a re-run.

### Making the upload key (once)

```sh
keytool -genkeypair -v -keystore upload.jks -alias upload \
  -keyalg RSA -keysize 4096 -validity 10000
base64 -i upload.jks | pbcopy   # macOS: copies the secret's value
```

Keep `upload.jks` and its passwords somewhere safe outside the repo. If it is lost, Play Console can reset the upload key (Setup → App signing → Request upload key reset); the app signing key Google holds is unaffected.

## Privacy policy

Play requires one: `public/privacy.html`, served at https://emblem-rogue.netlify.app/privacy.html (excluded from the service worker's navigation fallback so a returning player sees the page, not the game). Update it before a build starts collecting anything, for example a cloud-enabled build.
