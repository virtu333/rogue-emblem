UPGRADE MENU · TOUCH PATTERNS

The Home Base upgrade shop is the densest point-and-click screen in the game: 8px rows, hover tooltips, tiny cost buttons, scroll arrows. None of it survives touch. Below are three interaction patterns for iOS (landscape, per the mobile spec), mocked in an iPhone-13-class frame (844×390 pt) with real metaUpgrades.json data. Everything is tappable — try buying Hardy Recruits. Theme is Variant A from docs/mobile/ui-theme-guide.md.

Recommended. List rows carry only name, tier pips and a cost chip; tapping a row slides up a bottom sheet with the description, current → next effect, refund, and one big BUY button on the right (thumb side). The sheet replaces every hover tooltip — including milestone-lock explanations. Two taps per purchase, but zero accidental spends and room for full text at readable sizes.

Most console-like. Landscape split: scrollable list on the left, persistent detail panel on the right with BUY pinned at the bottom-right corner. No modal churn — best for browsing and comparing upgrades. Costs one third of the horizontal space, so rows carry less text.

Fastest, riskiest. Inline BUY button on every row plus an ⓘ target opening the same detail sheet as A. One tap per purchase suits repeat tier-buying, but adjacent-row misfires spend real Valor/Supply — if chosen, add an undo toast (5s) rather than a confirm dialog.

HAND-OFF NOTES (iOS)

RULES THAT APPLY TO EVERY OPTION

  • Kill hover. Every tooltip in HomeBaseScene (upgrade details, prerequisite explanations, milestone locks) must have a tap home: the detail sheet/panel. The existing _toggleTouchTooltip tap-tooltip is a stopgap, not the pattern.
  • 44pt minimum targets (Apple HIG): rows ≥48pt tall, BUY ≥44pt, category chips ≥34pt with padding taking them past 44pt effective. The current 14×10px cost buttons are ~4× too small.
  • Type floor: nothing below 7px 'Press Start 2P' / 10px body at 1× frame scale. Long descriptions move to the sheet/panel instead of shrinking.
  • One category currency at a time: highlight the active tab's currency (Valor for Lords/Equip/Skills, Supply for Recruits/Economy/Battalion) in the header, dim the other — same rule the desktop scene already applies, but with both totals always visible.
  • Scrolling is momentum touch-scroll on the list only (header/tabs fixed). Delete the [^]/[v] arrow buttons.
  • Milestone-locked rows keep the '???' mystery but the whole row is tappable and the sheet states the unlock requirement — no more hidden hover-only explanation.
  • Refund mode stops being a global toggle: REFUND lives in the detail sheet/panel next to BUY (with the −20 fee stated inline). Removes an entire mode and its footer banner.
  • Safe areas: respect env(safe-area-inset-*); in landscape the notch side needs ~34pt inset (mocked as the dark left gutter above). Bottom sheet sits above the home indicator.
  • Haptics (Capacitor later): light impact on buy, rigid on maxed/unaffordable tap.
  • Maxed rows flip pips to gold and the cost chip to a gold MAX badge — same BAR_FILLED_MAX language as desktop.

WHY A OVER B/C

  • A keeps rows full-width, so 'Deadly Arsenal II — Edric also starts with a Silver Sword (auto-equipped)' fits without truncation; B's rows can't hold description text at all.
  • A's two-tap purchase is self-confirming; C needs undo infrastructure.
  • B is the best fit if the team wants one codepath for tablet + phone (on iPad the sheet pattern feels undersized). A phone / B tablet is a reasonable split since both share row markup.

IMPLEMENTATION SKETCH

  • Build as an HTML overlay (like the mobile controls / roster revamp), not in-canvas: the shop is pure meta-state (MetaProgressionManager), no Phaser objects needed beyond scene routing.
  • Reuse list markup across options: .row = name + pips + cost chip; options differ only in what tap does. Ship A; C is a settings-flag experiment later ("Quick buy").
  • Group headers (GROWTHS / FLAT BONUSES / OTHER) mirror the desktop subgrouping for recruit_stats / lord_bonuses.
  • Category chips scroll horizontally with edge-fade; badge un-affordable-but-new states later if desired.
