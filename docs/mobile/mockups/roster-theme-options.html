ROGUE EMBLEM · MOBILE THEME OPTIONS

The mobile roster/menu revamp is more readable but off-brand — it currently reads as a generic slate admin panel. These are three restyles of the same roster screen, all built from tokens the game already ships (src/utils/uiStyles.js + the auth overlay CSS in index.html). Structure and touch targets are unchanged from the revamp — only the skin differs. Hand-off notes for the implementing agent are at the bottom.

Recommended baseline. Cheapest to adopt: it is a direct port of the existing auth-overlay + Phaser panel language. Square corners, 1px hairlines, navy #1a1a2e panels, gold selection states, 'Press Start 2P' headers, per-stat colors. Roughly a CSS-only diff on the current revamp.

Most "Fire Emblem." GBA-style bevelled blue windows built with layered box-shadow insets (no images), pixel-checker backdrop, text shadows for sprite-font depth. Higher effort; strongest vibe. Works best if applied everywhere at once — mixing it with flat panels looks broken.

Modern-tactical middle ground. Near-black ground, hairline panels with gold corner brackets, chamfered (clip-path) buttons and tabs, a ▸ cursor glyph on the selected unit. Distinctive without imitating GBA chrome; scales well to dense screens like convoy lists.

HAND-OFF NOTES

NON-NEGOTIABLES (ANY VARIANT)

  • Border radius ≤ 3px. The current 8–12px rounded cards are the single biggest vibe-killer. Pixel-art UIs are square.
  • 'Press Start 2P' for headers, labels, buttons, tabs. Keep the readable system/monospace font for body copy and long descriptions — that readability win was the point of the revamp. Budget ~8px width per character at 9px size; test longest names ("Acidic Swamp", "Light Sage", promoted class names).
  • Gold means "selected / focused / actionable", exactly as in-game: #e8b849 border + rgba(232,184,73,.06) fill, text to #f5d77a. Never a filled blue "primary button".
  • Stat colors from uiStyles.js: HP #ff6666, STR/MAG/SKL #ffdd44, SPD #66ddff, DEF/RES #66ff66, LCK/MOV #e0e0e0. The all-gold numbers in the current build lose information the game already encodes.
  • Panels are navy, not slate: fills #12111f / #1a1a2e on ground #0a0c1e, hairlines #3a3a55. No drop shadows — use borders and fills for depth (or Variant B's inset bevels).
  • Keep the touch ergonomics: ≥44px hit areas, current spacing, current information order. This is a reskin, not a relayout.
  • HP bars everywhere HP appears (green/yellow/red at 70%/40% per getHPBarColor) and mini stat bars in stat grids — bars are half the FE feel.
  • Micro-details that sell it: 2px gold rule under screen titles, ▸ or ◆ glyphs as cursors/markers, image-rendering: pixelated on any sprite/portrait images, font-variant-numeric: tabular-nums on stat columns, no opacity-fade hovers (color-shift to gold instead).

SUGGESTED PATH

  • Ship Variant A now as the shared base stylesheet for all HTML overlays (roster, shop, church, settings, deploy) — it is essentially token substitution on the current markup.
  • Layer C's brackets/chamfers on hero surfaces (screen headers, selected cards) if A feels too plain; the classes are additive.
  • Treat B as the aspirational skin — only adopt if committing to it across every overlay in one pass.
  • Whichever variant wins, extract the tokens into one shared CSS file so mobile overlays and the auth overlay stop diverging.
